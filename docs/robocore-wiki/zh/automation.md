# 网页自动化脚本

在「JSON 调试」的自动化任务脚本区域编辑、保存和运行任务。「停止循环」也在 JSON 调试内。每行填写一条 JSON 指令；指令参数见 [JSON 接口](json-api.md)。

网页 **JSON 调试 → 自动化任务脚本** 提供列表、读取、编辑、校验保存、运行、删除和本地导入/导出。每行一个 JSON 对象。保存不会执行动作；“运行”执行主板上保存的版本。

任务名为1–32位 ASCII 字母、数字、下划线或连字符。`boot` 为系统保留配置，不允许通过任务 API 读写；`boot_user` 在开机时自动循环执行，保存前务必检查全部动作。`up/down/left/right` 可用于已配置的 UI 模块按键任务。普通任务应使用自定义名称。

每个任务最多64步、16KB，每步原始 JSON 最多255字节，不能含 rid 或 T=300…399。上传时外层 T=303 还需要名称、转义和 rid，因此可上传的单步实际长度更短；网页会在发送前检查。不要在任务中反复写入 ID、基准等持久参数。

下面创建一个不移动电机的任务；逐条等待回复后再发下一条：

```json
{"T":301,"name":"demo","intro":"Read onboard IMU twice","rid":1}
{"T":303,"name":"demo","json":"{\"T\":740}","rid":2}
{"T":303,"name":"demo","json":"{\"T\":51,\"delay\":500}","rid":3}
{"T":303,"name":"demo","json":"{\"T\":740}","rid":4}
{"T":302,"name":"demo","offset":0,"rid":5}
{"T":308,"name":"demo","interval":0,"loop":1,"rid":6}
```

T=308 返回 status=started 表示开始执行，完成后同一 rid 发布 status=finished；`/api/info` 的 mission_running 可查询运行状态。状态完成只表示任务调度结束，不保证每个设备动作成功，仍需检查设备反馈。循环参数 -1 为无限循环，T=0 请求退出，不能当作电机急停。任务执行时先停止循环，再编辑或发送其它命令。

网页保存会先创建 `draft_` 草稿，逐步追加并回读校验，最后通过 T=310 替换目标。中断不会把半份脚本直接覆盖到目标任务；可以在列表读取草稿另存。目标存在时必须确认覆盖，T=310 需要 overwrite:true。超时不要立即重复执行；先查询列表和内容，确认是否已保存。
