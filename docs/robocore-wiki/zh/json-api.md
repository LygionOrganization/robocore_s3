# RoboCore S3 JSON 接口

RoboCore S3 完整固件使用人类可读的 JSON 指令控制设备。下文按用途列出指令、参数与发送示例。

## 通信方式

- **WebSocket**：`ws://192.168.4.1/ws`，每帧发送一个完整 JSON 文本；执行结果广播到已连接客户端。
- **HTTP**：`POST /api/cmd`，`Content-Type: application/json`。返回 `202 {"accepted":true,"policy":"latest-wins"}` 仅表示已接收；使用 `GET /api/result` 读取最新执行结果，按 `rid` 匹配。不是同步执行接口，不会返回历史结果。
- **USB CDC**：原生 USB 端口，每条 UTF-8 JSON 后发送 `\n`。持续读取换行分隔的回复；日志与 JSON 可能混合，忽略非 JSON 行。默认启用 USB 输出；若 `T=604` 关闭了 USB 输出，就无法从该端口读取结果。
- **ESP-NOW**：沿用原有 250 字节、零填充 JSON 消息帧，接收模式、可信 MAC 与信道按 `T=410…414` 配置。该传输不自动返回执行结果。

命令最大 255 字节（UTF-8 编码，不计换行）。HTTP/WebSocket 使用单个完整请求体/文本帧；分片或超长数据拒绝。JSON 必须有整数 `T`。可加入 `rid`（0…4294967295 整数）；执行结果原样返回，客户端同时最多等待一条命令，建议随机起始并递增，避免多客户端碰撞。

**最新命令优先**：当前命令不被抢占，仅保留最新的一条待执行指令。运行 1 时收到 2、3，之后执行 3。HTTP、WebSocket、USB、ESP-NOW 等共用这一队列。不保证每条指令执行，也不自动重试 EEPROM 写入。配置流程应逐条发出并等待对应结果，超时先读取状态再决定是否重试。

`{"T":0}` 在接收时设置退出循环标志、清空待执行命令，不入队，也没有结构化的执行回复。它会在循环检查点生效，不等于电机急停。连续速度用 `T=725,speed=0` 停止，关闭步进输出用 `T=726,enable=0`。永久任务占住执行器时，普通指令等待；先停止任务再执行调试命令。


自动化脚本的编辑、保存和运行见 [网页自动化脚本](automation.md)。

## 通用参数与使用顺序

JSON 的字段名区分大小写。表格中的示例是完整对象；按实际设备修改 ID、位置和速度后再发送。除明确标为可选的参数外，请填写示例中的全部字段。舵机与机械臂指令的参数范围因型号和机构而异，发送前应核对目标设备及机械行程。同步接口会校验数组长度、ID唯一性、位置范围与数值类型；SCS位置0–1023，其他同步位置0–4095。

| 字段 | 含义与单位 |
| --- | --- |
| `id` / `old_id` / `new_id` | 当前、原、新设备 ID。普通控制使用实际单个 ID；254 为部分旧协议的广播地址，读取/改 ID 不使用广播 |
| `baud` | 主控 UART 总线比特率，必须与设备一致；推荐优先使用 T=10，重启后按启动配置恢复 |
| `pos` | 舵机位置计数；SCS 常见范围 0–1023，STS/SMS/HLS 常见 0–4095，最终以具体型号及限位为准 |
| `spd` / `acc` | 舵机速度/加速度寄存器值。不是所有型号都接受 0，0 也不一定表示停止；HLS 使用非零速度 |
| `time` | SCS 运动时间，毫秒；与速度的优先关系按舵机协议。不要用 time=0、spd=0 作为停止命令 |
| `state` | 舵机扭矩：0 释放，1 使能；释放前支撑负载 |
| `cl` / `tor` | HLS 单轴电流限制 / 同步控制中每轴限制数组，寄存器值，不直接表示安培 |
| `idn` | 同步控制的设备数；所有数组长度均应等于 idn，范围1–16，不能超过连接设备数量；完整命令也必须能装入255字节 |
| `id[] / pos[] / spd[] / acc[] / tor[]` | 同索引属于同一轴。简化同步命令省略速度/加速度字段，并不提供与完整同步命令相同的控制选项 |
| `mid` / `ang` / `rad` | SCS 角度控制的参考计数 / 目标角度（度）/ 目标弧度，依赖 T=102 的换算设置；这两种指令的 spd 分别为度/秒、弧度/秒 |
| `move` | T=109/112/115：1 立即下发运动，0 预置寄存器动作，再用 T=118 触发 |
| `steps` / `angle` | T=102：每圈计数至少512、行程角度90–360°，用于舵机坐标换算 |
| `set` | T=200 为 `[灯序号,r,g,b]`，T=201 为 `[r,g,b]`；针对兼容旧灯控制器，不是 T=712 的色值规范 |
| `line` / `text` / `update` | OLED 行号1–4、ASCII文本、是否刷新（0暂存/1刷新）；T=203 刷新，T=204 的 l1…l4 一起更新 |
| `num` | 旧 Node 接口的灯数量/刷新范围，按对应设备协议；Node 控制优先 T=712 |
| `freq` / `duration` | 蜂鸣器频率Hz、持续毫秒；duration=0 不表示持续鸣叫 |
| `ang[] / rad[] / pos[]` | 机械臂四关节角度、弧度、零位计数数组；顺序为底座、肩、肘、夹爪 |
| `xyzg` | 机械臂 `[x,y,z,g]`，位置为mm、夹爪角度为度；工作空间取决于匹配的机械臂结构 |
| `rbzg` | 机械臂 `[r,b,z,g]`，r/z为mm、底座角b和夹爪角g为度 |
| `spd` / `br`（机械臂） | 平滑运动参数、底座插值比例；不是舵机原始 spd 单位，请使用匹配机械臂的配置 |
| `flag` / `hz` | T=145：周期反馈开关0/1、反馈频率；不会替换 T=740 的板载惯性传感器读取 |
| `flag` / `axis` / `delta` | T=146：连续运动开关0/1、预设坐标轴、每次增量；仅适用于匹配的机械臂应用 |

先用 T=700 扫描，再用对应反馈指令读取设备，最后测试低速、限位内的动作。同一组 IO4/IO5 的 TTL 与总线设备 RS485 共用波特率和数据，不能当作独立串口。外部 CAN/RS485 在 IO13/IO14，由开关与运行程序共同决定通信功能。

### 同步舵机示例

两只 STS/SMS 舵机应有不同 ID，并支持目标位置。先分别读取 T=15，再发送：

```json
{"T":16,"id":[1,2],"idn":2,"pos":[2047,2100],"spd":[100,100],"acc":[10,10]}
```

若只是要读取板子本身的运动数据，使用 `{"T":740}`；它读取板载 QMI8658A，不是外接 TTL IMU。

## 发送与接收示例

以下接收内容是示意，实际 ID 和读数以设备为准。HTTP 使用 GET /api/result 获取接收结果；WebSocket 直接接收推送。

| 操作 | 发送 | 接收示例 |
| --- | --- | --- |
| 扫描设备 | `{"T":700,"first":0,"last":20,"rid":1}` | `{"T":700,"rid":1,"ok":true,"ids":[1,5],"first":0,"last":20}` |
| 读取编码器 | `{"T":732,"id":1,"rid":2}` | `{"T":732,"rid":2,"id":1,"ok":true,"bus_error":0,"reply_status":0,"pos":2048,"speed":0}` |
| IMU 不可用 | `{"T":740,"rid":3}` | `{"T":740,"rid":3,"ok":false,"present":false,"error":"imu_not_present"}` |

`ok:false` 表示参数或设备通信失败。部分指令返回 `dispatched:true`，只表示处理器已完成分发，不代表电机动作成功。设备 ID 设置 T=13/23/33/710/720 会检查新 ID；编码器与步进驱动共用 T=720。

## 只读端点

| 端点 | 内容 |
| --- | --- |
| GET /api/info | 固件、总线波特率、IMU、任务状态，以及 sta_state、sta_ip、ap_ip、sta_ssid；无密码 |
| GET /api/result | 最新一条执行结果，通过 rid 匹配；不保存历史 |
| GET /api/imu | 板载 IMU 最新有效快照；只读，不进入指令队列，字段见下文 |

## IMU 反馈（T=740 / GET /api/imu）

`GET /api/imu` 直接返回只读快照，不进入指令队列。单次指令发送 `{"T":740,"rid":1}`，成功接收格式如下（数值仅为示例）：

```json
{"T":740,"rid":1,"ok":true,"present":true,"address":106,"sample_age_ms":2,"sample_count":123,"temperature_c":25.0,"accel_g":[0,0,1],"gyro_dps":[0,0,0]}
```

| 字段 | 含义 |
| --- | --- |
| `present` / `address` | 是否检测到传感器 / 十进制 I2C 地址 |
| `accel_g` / `gyro_dps` | X、Y、Z 轴加速度（g）/ 角速度（度/秒）|
| `temperature_c` | 传感器温度（℃）|
| `sample_count` | 24 位循环样本计数；相同计数表示同一份样本 |
| `sample_age_ms` | 缓存样本距今的毫秒数；无有效样本为 -1 |
| `ok` / `error` | 仅在 ok=true 时使用测量值；超过 100 ms 的旧样本返回 imu_no_fresh_sample |

实时读取应逐次等待响应，建议每秒约 10 次或更低，不保存请求历史。网页估算横滚、俯仰和相对航向；六轴 IMU 不提供绝对航向。

T=723/732 的 reply_status 表示位置和速度读取回复中的合并状态标志。T=723 的 device_status 来自实际驱动状态寄存器，device_fault、current_limited、limit_active、target_out_of_range 分别表示故障、限流、限位和目标越界；限流不等于故障。

## TTL 6DOF IMU

在 **TTL 6DOF IMU** 页面可单次读取、实时查看反馈和修改 ID。先用 T=700 扫描（范围须包含 200），选择 ID 后进入面板。上游例程使用 ID 200、1 Mbps；请以实际设备设置为准。修改 ID 时逐个接入目标设备。

读取：`{"T":751,"id":200,"rid":1}`。改 ID：`{"T":750,"id":200,"new_id":201,"rid":2}`。等待匹配的 `rid` 和 `ok:true`；修改后使用新 ID 再读取。超时的配置写入不得自动重试。

反馈包含 `accel_raw`、`gyro_raw`（三个带符号原始计数）和 `quaternion_xyzw`（四个浮点数）。不沿用板载 QMI8658A 的单位或专用接口。SDK 未定义物理量换算映射，也未提供采样计数；总线读取成功不能证明传感器内部数据仍在更新。网页每次等结果后间隔 200 ms 再读，1.5 秒无有效反馈即清空实时数值；离开页面暂停采集。三维模型复用板载 IMU 绘制代码，直接使用设备四元数，显示横滚、俯仰和相对航向，并支持航向归零。等待回复期间保留上一帧，不清空闪烁；反馈过期时冻结模型并清空数值。六轴航向为相对值，会漂移。

协议来源：[上游 Python IMU SDK](https://github.com/ftservo/FTServo_Python/blob/main/scservo_sdk/imu.py)，核对的 blob 为 `2028869faa4bb9e52b688cc8e1089a73bd0c91ef`。读取 56–78 寄存器，ID 位于 5，EEPROM 锁位于 55。加速度/角速度采用符号幅值，四元数 XYZ 为 binary16，W 取非负平方根（XYZ 平方和超过 1 时取 0），与 SDK 一致。
