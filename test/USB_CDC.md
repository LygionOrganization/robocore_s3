# USB CDC 接收约定与验证

- 使用 Arduino `USBCDC::onEvent`，不再定义 TinyUSB 底层回调。
- EVENT 只收包、校验 JSON、提交命令，不调用执行器或输出日志。接收不依赖 `loop()`。
- 每条 JSON 以 `\n` 结束，兼容 `\r\n`，最多 255 字节（不计行结束符）。超长行、带 NUL 的行、非法 JSON 和缺少整数 `T` 的指令会丢弃。
- 共享命令队列长度为 1，所有入队入口使用 `xQueueOverwrite`：正在执行的命令继续执行，等待中的命令被最新有效指令替换。USB、UART、WebSocket、HTTP、ESP-NOW、按钮共用这一规则。
- `{"T":0}` 在接收时清空待执行命令并设置原子停止标记，不入队，不因后续普通命令覆盖而失效。循环在原有检查点响应停止；不会强行打断总线 I/O 或 `delay()`。
- `runMission()` 的永久循环行为保留。普通命令不会自动终止永久任务，需要先发停止命令。
- USB RX 溢出后丢弃到下一个换行，恢复组包。EVENT 每次只处理进入时已排队的字节，避免连续发送占住事件任务。
- 修复短字符串被队列按 256 字节越界读取、Web 接收缓冲越界，以及命令解析和部分反馈对象跨任务共用的问题。原有启动 MissionTask 与主循环并行执行总线操作的设计保留。

## 自动验证

在项目根目录运行（Windows MSVC Build Tools）：

```powershell
python test/run_usb_cdc_tests.py
pio run
```

主机测试提取实际接收与提交函数，使用真实 ArduinoJson、模拟 USB 字节流和单元素队列，验证分包、粘包、容量边界、NUL、超长数据、溢出恢复、断连、停止以及 20 万条命令覆盖。它不模拟 FreeRTOS 调度和 USB 硬件。

已验证构建：pioarduino 55.3.30 / Arduino-ESP32 3.3.0 / ArduinoJson 7.4.3。`platformio.ini` 已固定平台发行版 55.03.30 与本机验证过的库版本，避免不同电脑自动解析到不同依赖。此修改消除了应用重复定义 `tud_cdc_rx_cb` 的原因，不保证任意未来依赖版本都兼容整个项目。

## 实机压力验证

烧录后，关闭占用端口的串口监视器，运行：

```powershell
python python_example/usb_cdc/usb_cdc_stress.py COM15 --seconds 1800 --rate 2000
```

替换为实际 USB CDC 端口。脚本发送只读的 `T=603` 查询并持续读取反馈；发送计数不等于执行计数，丢失中间命令是预期行为。若当前有永久任务占用执行器，需先按使用场景停止该任务，查询才会被执行。

检查长时间运行后是否仍能查询、是否有复位；再用实际总线命令验证最新目标生效。另行验证永久任务运行时 `{"T":0}` 能在原有检查点停止。

上位机应持续读取反馈。固件的 UsbOutput 适配器只按当前空闲 FIFO 容量写入，每次 write 最多等待 10ms，拥堵时丢弃剩余输出，并在恢复时补换行以重新同步文本边界。这避免了本机 Arduino 3.3.0 原始 USB write 在缓冲满时持续等待的问题。接收 EVENT 本身没有发送操作。主机测试覆盖缓冲满、超时和恢复；不能代替实机长时间压力测试。
